# CVE-2023-48409 Notes

Integer overflow in the buffer liveness update ioctl in the Mali pixel
module, combined with a kernel pointer leak through the timeline stream.

## Value for Manvil

### KBASE_API_VERSION encoding

The disclosure defines a version encoding used across the API surface:

#define KBASE_API_VERSION(major, minor) ((((major) & 0xFFF) << 20) | \
                                         (((minor) & 0xFFF) << 8)  | \
                                         ((0 & 0xFF) << 0))

#define KBASE_API_MIN(api_version) ((api_version >>  8) & 0xFFF)
#define KBASE_API_MAJ(api_version) ((api_version >> 20) & 0xFFF)

The u32 layout is:

  bits 31-20  major
  bits 19-8   minor
  bits  7-0   patch

Manvil should adopt this encoding for its own API version reporting and
for comparing against the version reported by the kernel.

### kbase_kcpu_command_queue size

The disclosure states that the kernel-side kbase_kcpu_command_queue
object occupies 0x38C8 bytes. It is large enough that it is served by
the page allocator rather than a slab cache.

Implication for Manvil: KCPU queue objects are heavy. A process should
create only what it needs. The typical requirement is one KCPU queue per
context.

### Pixel specific ioctl 67

The disclosure includes a struct definition for a Pixel-specific ioctl:

struct kbase_ioctl_buffer_liveness_update {
    __u64 live_ranges_address;
    __u64 live_ranges_count;
    __u64 buffer_va_address;
    __u64 buffer_sizes_address;
    __u64 buffer_count;
};

#define KBASE_IOCTL_BUFFER_LIVENESS_UPDATE \
    _IOW(KBASE_IOCTL_TYPE, 67, struct kbase_ioctl_buffer_liveness_update)

This ioctl is not part of the standard Kbase interface. It exists only
on Google Pixel kernels that include the mali_pixel module. Manvil does
not implement it. If it runs on a Pixel, it must recognize that this
capability may exist and ignore it.

### Timeline stream leak confirmation

The disclosure confirms that the timeline stream
(KBASE_IOCTL_TLSTREAM_ACQUIRE) serializes kernel pointers into the
message buffer. One example is
__kbase_tlstream_tl_kbase_kcpuqueue_enqueue_fence_wait, which writes
the kbase_kcpu_command_queue pointer and a dma_fence pointer.

Manvil does not use the timeline stream to obtain kernel pointers.
It may use the stream for legitimate tracing and diagnostics, in which
case pointers that appear in the messages should be treated as opaque
identifiers, not as addresses to dereference.

## Value for Manvil

Medium. Provides a version encoding convention, an object size
reference, and confirmation of the timeline stream behavior. No new
CSF protocol definitions.

## Non-reusable content

The heap grooming technique, pipe_buffer manipulation, and kernel
symbol offsets are not recorded. They are specific to the exploit and
to the target device.
