# CVE-2025-0072 and CVE-2025-0073 Notes

Two advisories published by Google SecurityLab for Mali GPU kernel
driver vulnerabilities discovered by Man Yue Mo in late 2024 and early
2025. Both affect the CSG user page allocation path.

## CVE-2025-0072

Use-after-free in the queue rebind path. The name of the exploit source
file is mali_userio.c, which confirms that the affected subsystem is the
user IO pages allocated by the queue bind operation.

Reported: December 2024
Target: Pixel 8, build AP3A.241105.007 (November 2024 patch)

### Observations from the exploit log

gpu_addr 5ffff94000
group_handle 1 cookie 30000
group_handle 1 cookie 30000

The cookie 30000 is the mmap handle returned by CS_QUEUE_BIND. Its value
corresponds to three pages (0x3000). This matches
BASEP_MEM_CSF_USER_IO_PAGES_HANDLE (48 << 12 = 0x30000) for the first
queue bound in a group.

Manvil should treat the mmap handle as opaque but should expect this
value on the first bind of a group.

The exploit reuses the same helper files as CVE-2023-6241
(mem_read_write.c, mempool_utils.c), which indicates that the memory
management patterns are stable across versions.

## CVE-2025-0073

Use-after-free in CSG_CS_USER_PAGE_ALLOCATION. This is a new capability
introduced in kernel driver r53 and later. It changes the ownership of
the user IO pages.

### Ownership model change

Earlier versions (r32 through r52):

  The queue owns its user IO pages. They are allocated when the queue is
  bound and freed when the queue is unbound.

Version r53 and later:

  The queue group owns the user IO pages. The queue holds references
  into the group's physical page array (queue->group->phys[0] and
  queue->group->phys[1]). The pages are freed when the group is
  terminated, not when the queue is unbound.

### Implication for Manvil

On kernels that support CSG_CS_USER_PAGE_ALLOCATION:

  Rebinding a queue to a different group, or unbounding it and rebinding
  to the same group, does not allocate fresh user IO pages. The pages
  stay allocated until the group is destroyed.

  This is faster for repeated bind and unbind cycles. It also means that
  code must be careful not to hold stale pointers to user IO pages after
  a group is terminated.

Manvil should query the capability during device initialization and use
the group-owned model when available.

## Non-reusable content

The exploit payloads for both CVEs, the heap grooming strategies, and
the target-specific kernel offsets are not recorded.

## Value for Manvil

Medium for CVE-2025-0072 (confirms mmap handle value and pattern
stability across versions).

High for CVE-2025-0073 (documents the user page ownership model change
in r53 and later, which affects the design of the queue bind and group
lifetime code).
